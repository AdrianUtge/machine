# 04 — Passerelle ESP8266 (NodeMCU)

Dossier : `firmware/ESP8266/` (PlatformIO, env `nodemcuv2`).
Fichier principal : `src/main.cpp`.

## Rôle

L'ESP8266 est la **passerelle WiFi** entre le backend et l'OpenRB-150 :

1. crée un **point d'accès WiFi** (mode AP) — le PC se connecte à SON réseau ;
2. expose un **serveur REST** (`/api/status`, `/api/command`) sur le port 8080 ;
3. **relaie** les commandes vers l'OpenRB en série (19200) ;
4. **met en cache** la télémétrie streamée par l'OpenRB → réponses instantanées.

Il ne contient **aucune logique métier** (pas de contrôle de force).

## Câblage série (vers l'OpenRB-150)

```
ESP TX = GPIO12 (D6)  ──────▶  OpenRB Serial3 RX (D13)
ESP RX = GPIO14 (D5)  ◀──────  OpenRB Serial3 TX (D14)
GND commun
SoftwareSerial @ 19200 bauds   (baud modéré = fiable malgré le WiFi)
```

LED intégrée (D4/GPIO2, actif bas) : clignote ~1 Hz = vivant.

## Boucle principale (`loop()`)

```
loop():
  pumpOpenRB()          # lit le flux série OpenRB en continu -> met à jour `live`
  server.handleClient() # traite les requêtes HTTP
  blink LED
```

`pumpOpenRB()` est le **seul lecteur** du port série. `sendToOpenRB()` n'écrit
que (fire-and-forget) : pas d'attente de réponse → pas de fenêtre de silence.

## Cache live (`struct OpenRbLive`)

Alimenté par `parseOpenRbLine()` à chaque ligne reçue : `rbState`, `frequency`,
`positions[4]`, `sensors[4]`, `slaveOnline`, `lastDataMs`. `GET /api/status`
sérialise ce cache → pas d'aller-retour série par requête.

`rb_online` = OpenRB frais (< 1 s) **ET** `SLAVE:ONLINE`.

## Mémoire d'état (reprise après reload)

L'ESP mémorise `cycleStart` (epoch ms, reçu au START), `frequency` et
`forces[4]` (consignes). À la reconnexion, le backend les relit → l'UI reprend
l'état en cours.

## Sécurité (jeton Bearer)

Chaque requête (sauf preflight CORS `OPTIONS`) exige
`Authorization: Bearer <AUTH_TOKEN>`. Le jeton provient de **`secrets.h`**,
généré au build depuis `.machine_config.ini` (`[nodemcu].key`).

## Configuration & secrets

```
.machine_config.ini  --(gen_secrets.py au build)-->  include/secrets.h  -->  config.h  -->  main.cpp
```

- `gen_secrets.py` (extra_scripts `pre:`) lit le `.ini` et écrit `secrets.h`
  (`SECRET_WIFI_SSID/PASSWORD/AUTH_TOKEN/HTTP_PORT`). **Gitignoré.**
- `config.h` inclut `secrets.h` s'il existe, sinon utilise des défauts → le
  firmware compile toujours.
- **Après toute modif du `.ini`** : `pio run` régénère `secrets.h`, puis
  **re-flasher l'ESP**.

## Build & flash

```bash
cd firmware/ESP8266
pio run                 # build (génère secrets.h depuis ../../.machine_config.ini)
pio run -t upload       # flash
pio device monitor -b 115200   # logs USB
```

Dépendance externe : `bblanchon/ArduinoJson`. (ESP8266WiFi/WebServer/
SoftwareSerial = core Arduino.) `WebSockets` a été retiré (inutilisé).

## Pièges connus

- **Brownout / perte WiFi** : souvent une **alim instable** (hub USB partagé
  OpenRB + Dynamixel), pas le code. Alimenter l'ESP séparément. Voir
  [11_TROUBLESHOOTING.md](11_TROUBLESHOOTING.md).
- L'ESP ne gère **qu'une** connexion HTTP à la fois → le backend sérialise ses
  accès (`_http_lock`).
- En mode AP, l'IP est **toujours** `192.168.4.1`.
